# dozview — provenance of the committed binary

`Sources/DozerKit/Resources/dozview` is a **committed build artefact**: the guest half of workspace
rules (`.dozignore` / `.dozreadonly`). It is copied to `/usr/local/lib/doz/bin/dozview` (never run
from the share it serves) when a share's Mac folder holds a rule file, at a fresh boot, a wake or a
session start, and serves the share's guest path (e.g. `/workspace`) as a filtering view. It is the pin,
like `deckhold` and `doznet`; consumers never need Zig. `make dozview` rewrites the (auto) lines after a
rebuild; `make dozview-verify` rebuilds from scratch and checks the committed bytes match.

| command | `zig cc -target aarch64-linux-musl -static -O2 -s -Wall -Wextra -Wno-unused-parameter -I match/include dozview.c match/*.c` (run in this directory, so no checkout path is recorded) |
| reproducible | yes — two `FORCE=1` rebuilds produced identical bytes |
| tables | `match/dozfold_tables.h` is generated by `Scripts/gen-dozfold-tables.py` (python3's `unicodedata` 13.0), which also writes `Sources/DozerKit/DozFoldTables.swift` — run it, then `make dozview` |

What it does (details in the source header): speaks the raw `/dev/fuse` protocol (no libfuse — LGPL-2.1
would oblige us to ship relinkable objects), serves the share bound privately at `/run/doz/raw/<tag>`
(0700) with `allow_other,default_permissions`, a 1 s entry/attribute cache and readdirplus, from 6
request threads; locks or hides what `.dozignore` selects (Docker's `.dockerignore` semantics,
BuildKit's walker — `match/dozmatch.c`, the same file `make test` runs against the real-Docker vectors),
makes `.dozreadonly`'s paths read-only, reloads the rules within ~250 ms of a change (or on SIGHUP) and
invalidates the kernel's cached entries; re-opens its link to the share on SIGUSR1 (the wake's re-mount
sends it) and never trusts a dead one. A supervisor process keeps the FUSE connection and restarts a
worker that dies. **Not a security boundary**: root in the guest can stop it.
